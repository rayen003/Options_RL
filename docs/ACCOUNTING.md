# Accounting and diagnostic charts

This note records first correction to simulator ledger. Purpose: make every trade, reward, and chart explainable from cash flows. It does **not** validate a trading strategy.

## Ledger rules

One option contract represents 100 units of underlying. Let `m` be model mid-price, `s` full proportional quoted spread (`transaction_cost`, default 0.02), `q` signed contract position, and `C` cash.

- Ask = `m × (1 + s/2)`; bid = `m × (1 − s/2)`.
- Buying `Δq > 0`: `C_new = C_old − Δq × ask × 100`.
- Selling `Δq < 0`: `C_new = C_old − Δq × bid × 100` (negative `Δq` means cash received).
- Portfolio value = `C + 100 × (q_call × m_call + q_put × m_put)`.
- Base step reward = `(portfolio_value_after − portfolio_value_before) / initial_cash`.

Bid/ask cost is already inside cash and therefore inside value change. It is reported separately for explanation, **not subtracted from reward again**. A buy or sell action sets target position to +1 or −1; reversal trades two contracts at relevant side of spread. At time limit, long positions sell at bid and short positions buy at ask; at expiry, intrinsic value settles without quoted spread. Final observation, reward, and reported value use **post-liquidation** state.

### Worked example

Start with $10,000 cash, no positions, call mid-price $5.00, full spread 2%. Buy one call at ask $5.05 × 100 = $505. Cash becomes $9,495; marked option value is $500; portfolio value becomes $9,995. The $5 drop is entry half-spread, not a $500 profit. Sell immediately at bid $4.95 × 100 = $495: cash and portfolio value become $9,990. Total round-trip spread cost is $10.

Old code left cash at $10,000 on entry while adding $500 of option value. It also calculated final reward before liquidation. Both errors could distort PPO training and plots.

## Reading episode_summary.png

1. **Portfolio value ($):** cash plus marked open positions; final point includes liquidation.
2. **Daily P&L ($):** first difference of portfolio value. Includes market moves, fills, spread, and simplified cash financing.
3. **Drawdown (%):** `100 × (value / highest value so far − 1)`. Zero means new peak; −5% means 5% below prior peak.

Chart title reports one episode's terminal return and maximum drawdown. These are descriptive diagnostics on a synthetic path, not confidence intervals, backtest returns, or proof of trading edge. Shaped RL reward can disagree with dollar P&L because it contains extra policy incentives.

## Verification and limits

`tests/test_accounting.py` checks long and short entries, two-fill reversal, hold, final liquidation, and reward/value consistency. `tests/test_visualize.py` checks P&L/drawdown calculations and chart labels. Run `python -m pytest -q`.

Financing remains simplified: daily risk-free interest applies to cash balance; there is no collateral or margin check. Agent directly observes regime, and prices are generated by BSM using simulator volatility. Evaluation and training-result claims need separate work; no old model should be reused after ledger correction.
